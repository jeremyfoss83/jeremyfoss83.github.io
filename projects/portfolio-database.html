Database Systems · Case Study 03

Cryptocurrency Portfolio Management Database

A seven-table relational system designed to preserve integrity across users, portfolios, transactions, assets, alerts, and supporting entities.

CourseDatabase Design
TermSpring 2025
ToolsSQL · ERD
Outcome150 / 150

The problem

A portfolio system needs to track ownership and transactions while preventing inconsistent or invalid records. The project translated business rules into a relational structure with explicit integrity controls.

Database design

I designed and implemented seven related tables covering portfolio, cryptocurrency, transaction, user, AI-agent, threshold, and lookup responsibilities.

  • Created an entity-relationship diagram before implementation.
  • Defined primary and foreign keys for traceable relationships.
  • Applied UNIQUE and CHECK constraints.
  • Added indexes supporting expected access patterns.
  • Created test data and analytical queries.
  • Implemented a reusable view and transaction logging.

Automated alert logic

Trigger-based logic supported threshold monitoring so that relevant changes could generate an alert record. This connected the database design to an operational use case rather than leaving the schema as a static diagram.

Correction from the previous portfolio: The verified implementation contains seven tables, not eight. This case study uses the evidence-supported count.

What I would improve next

I would publish a sanitized schema and seed dataset, add migration scripts, document query plans, and build a small read-only interface that demonstrates the database without exposing credentials.
